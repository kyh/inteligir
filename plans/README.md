## Recommended order

**Ship first (data loss + unpatched security):** 001, 002, 003. These are the
only findings where doing nothing has a compounding cost — 001 can destroy a
user's vault across every synced device, 002 leaves an unpatchable HIGH advisory
on the agent runtime, 003 leaves the only public auth surface unthrottled.

**Then:** 004 (biggest perf win, depends on 001), 012 (cheap, unblocks nothing
but fixes docs that actively mislead), 005/006/007.

**Opportunistic:** 008–011, 013 — real but small.

**Product work, when you want it:** 014 (cheapest capability add), 015, 016.

## Dependency notes

- **004 requires 001**: both change `VaultManager`'s listing path. 001 makes a
  missing/unreadable root throw (instead of silently listing empty); 004 caches
  the crawl. Landing 004 first would build a cache over the unsafe semantics.
- **013 softly follows 012**: 012 fixes the README block that documents the
  format-before-gates rule that 013 enforces. They can land independently.
- **009 conflicts with nothing on disk** but touches the renderer's highest-risk
  file (`vault-context.tsx`). Don't run it concurrently with other renderer work.

## Honest caveat on 009

Extracting the listing and file-ops hooks is a genuine readability win, but it
leaves the _actually dangerous_ concern — the note-runtime ref/ordering dance
that must flush the open note's edits before the next note opens — exactly where
it is. Do not mistake 009 for risk reduction. If the goal is to de-risk that
ordering, that is a different and scarier plan, and it should start with
characterization tests, not an extraction.

## Findings considered and rejected

Recorded so they aren't re-audited next run:

- **Renderer `postMessage` broker missing an origin check** (raised by the
  correctness audit): FALSE POSITIVE. `html-app-view.tsx:179` already checks
  `event.source !== frame.contentWindow` before the token check. Verified in the
  live code.
- **LAN remote access serves the Bridge over plaintext `ws://`** (security
  audit): real, but it's an opt-in, off-by-default feature on a trusted-LAN
  threat model. TLS on a LAN socket needs cert trust on peers — disproportionate
  today. Revisit if remote access ever leaves LAN scope, or ship token
  rotation/expiry as the cheaper half.
- **Sequential reconcile op execution** (perf audit — N serial round-trips on
  first sync): real, but pushes must stay ordered against base advancement and
  the DO serializes them server-side anyway. Only independent _pulls_ are safely
  parallelizable, which is a narrow win for a real correctness risk. Not worth it
  until someone reports a slow initial sync.
- **Rename re-parses every doc in the vault; `ensureResolved()` rebuilds the whole
  link map per save** (perf audit): both real and both O(vault). Deferred, not
  rejected — they're off the interactive path (rename is user-initiated and
  one-shot; resolution is lazy behind a debounce) and the fixes are L-effort with
  MED correctness risk (shadow-protection semantics). Revisit when a vault gets
  big enough to feel it.
- **`apps/web` has zero tests**: correct, and fine. It's a landing page, not a
  critical path.
- **Column-resize drag listeners leak on unmount mid-drag** (correctness audit):
  real but trivially bounded — the listeners hold a stale editor for the lifetime
  of one aborted drag. Folded into no plan; fix opportunistically if touching
  `column-node.tsx`.
- **Two markdown/math/highlight stacks bundled (streamdown + katex/lowlight/mermaid)**
  (deps audit): real duplication, but the editor and the AI chat have genuinely
  different rendering needs and consolidating risks regressing one surface. The
  one cheap piece — confirming whether the standalone `mermaid` dep is actually
  needed or is dead weight — is worth a one-line check next time someone touches
  desktop deps.
- **`@expo/dom-webview` and `lightningcss` pnpm overrides are stale/vestigial**
  (deps audit): probably true, but both need a real mobile/web build loop to
  verify safely. Explicitly excluded from plan 012 for that reason.
- Previously-settled decisions confirmed still sound, do not re-raise: IPC registry
  triple-maintenance (no codegen), `@repo/ui` staying one package, Base+React kit
  pairing, turbo test caching off, HTTP-200 `{ok:false}` sync conflicts,
  first-user-owns-vault, the agent's unconfined fs access, and the ephemeral
  (unwatched) vault index.
