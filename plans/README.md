## Findings considered and rejected (do not re-audit)

- **IPC "triple maintenance" restructure** — measured: adding a channel is 3
  typecheck-enforced edits (registry, handler, fixture-bridge); preload and
  renderer auto-derive. The cost buys compile-time contract enforcement across
  four surfaces. Not worth a generator.
- **Splitting/trimming `@repo/ui`** — all 22 components have consumers
  (desktop ~28 import sites, web 7). No dead vendored components. Justified as-is.
- **Server "Manager" abstraction teardown** — VaultManager, KnowledgeManager,
  DelegationManager etc. are concrete stateful classes, not single-impl
  interfaces; no pass-through layer exists to delete.
- **Base+React kit-pairing reduction** — correctly applied: only the 14
  serializer-mirror kits are in `BASE_KIT`; live-only surfaces are excluded;
  no dead kits.
- **Watcher-scoped knowledge refresh** (stat only changed paths) — `fs.watch`
  coarseness makes the full-scan the safety net; per-save cost is ~2k stat
  syscalls, acceptable. Revisit only with profiling data (see plan 011's
  out-of-scope note).
- **Turbo test caching** (`test` is `cache: false`) — deliberate blanket-off;
  enabling per-package caching risks stale-green without careful `inputs`.
  Deferred as a judgment call; the doc claiming caching exists is fixed in
  plan 002 instead.
- **Gitignoring `worker-configuration.d.ts`** — typecheck consumes it and
  regeneration requires wrangler; kept committed, marked `linguist-generated
-diff` in plan 010.
- **First-user-owns-vault authz model** — enforcement verified correct
  (`onConflictDoNothing` + re-read; vaultId is a per-install random UUID).
  The model itself is a decided tradeoff.
- **Version-conflict as HTTP-200 `{ok:false}` value** — decided design,
  correct as implemented.
- **Agent's unconfined filesystem access** — intentional: the agent equals
  the user; the `./vault` symlink adds no new escape (the renderer IPC path is
  the one being hardened, in plan 007).
